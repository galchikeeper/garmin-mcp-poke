# Garmin 안정화 구현·검증 결과

검증일: 2026-09-28. **로컬 구현 완료, 운영 반영·실측은 미완료**입니다.
빈(Bin) 앱의 데이터 삭제, 운영 배포, Garmin 로그인·토큰 교환은 하지 않았습니다.

## 구현 범위

- Fernet 암호화 Gist에 토큰과 쿨다운 상태를 함께 저장하고 재시작 시 복원.
- Gist 읽기 실패 시 과거 환경변수로 쿨다운을 덮어쓰지 않고 호출 차단.
- 서버 비밀번호 로그인 제거. 시작 및 `/health`는 Garmin에 접근하지 않음.
- 단일 프로세스의 동시 요청 직렬화, OAuth2 갱신 직후 저장.
- 이미 인증된 요청을 포함해 Garmin 호출 전 복구 보호 시간을 먼저 저장.
  호출 후 429 상태 저장에 실패해도 재시작 직후 호출이 반복되지 않음.
- 실패 백오프 15분/1시간/6시간/24시간, 429는 최소 6시간 및 더 긴 Retry-After 적용.
- 실패한 도구를 자동 재실행하지 않음. 기존 운동 조회·예약의 raw Garth 경로도 보호.
- `/health`에 저장 출처·토큰 로드 여부·쿨다운·마지막 성공/갱신·저장 오류 추가.
- OAuth 서명·응답·건강 데이터가 라이브러리 로그를 통해 노출되지 않도록 차단.
- 단 한 번의 명시적 로컬 시드 로그인 도구. 원격 저장과 0600 로컬 백업을 독립 시도.
- 킵얼라이브는 **비활성 템플릿**만 제공. 스케줄러나 모니터는 등록하지 않음.

## 실제 검증 결과

| 검증 | 결과 |
|---|---|
| Python 3.11.16 격리 환경 | 75 passed, 3 dependency deprecation warnings |
| Python 3.14.5 격리 환경 | 75 passed, 3 dependency deprecation warnings |
| 기존 도구 계약 | 11개 모듈, 90개 도구의 이름·입출력 스키마·설명·annotations 동일 |
| 의존성 일관성 | 두 환경에서 `pip check` 통과 |
| 문법·공백 | `compileall`, `git diff --check` 통과 |
| Gist 실저장 확인 | 승인 후 암호화 초기 상태 생성·복호화 확인. Garmin 토큰 없음 |
| 시크릿 파일 | `.secrets/store.env` 권한 0600, Git 제외 확인 |

핵심 고정 버전: garminconnect 0.2.40, garth 0.5.21, FastMCP 2.14.7.
운영 설정 파일의 Python 3.11.9와 동일한 **3.11 계열**로 검증했지만,
Render의 Linux 환경 또는 정확히 3.11.9에서 실행한 결과는 아닙니다.

테스트는 fake 클라이언트·저장소·시계와 실제 라이브러리의 오프라인 토큰 로드,
더미 OAuth 서명을 사용했습니다. 실제 계정에 대한 90개 API의 성공을 뜻하지 않습니다.
회귀 테스트에는 동시 요청, 재시작 후 쿨다운, 저장 실패, 429 escalation,
헬스체크의 무통신·응답성, 토큰 비노출, 기존 raw 운동 호출 경로가 포함됩니다.
시작 당시 서버 저장소에는 자동 테스트가 없었습니다.

## 아직 하지 않은 것

- Render 환경변수 변경, 서비스 배포·재배포, 운영 `/health`를 이용한 깨우기.
- 실제 Garmin 비밀번호 로그인, OAuth 교환, 데이터 읽기·쓰기·삭제.
- UptimeRobot 등록 또는 GitHub Actions 예약 활성화.
- GitHub 원격 브랜치 push, PR, main 변경.
- Bin 앱 UX/UI 작업은 이 Garmin 안정화 변경에 포함하지 않음.

Render 접근이 확인되지 않았으므로 무료 서비스 수·잔여 시간도 검증되지 않았습니다.
별도의 gist-only GitHub PAT는 아직 설정하지 않았으며, 기존 GitHub CLI의
넓은 권한 자격증명을 Render로 내보내지 않았습니다.

## 남은 운영 검증과 주의

1. 암호화 키를 개인 비밀 저장소에 백업하고 Render 접근 및 gist-only PAT 준비.
   `.secrets/store.env`는 로컬 평문 설정이므로 공유·커밋·로그 출력 금지.
2. 별도 운영 반영 승인 후에만 환경변수와 검토된 코드를 적용.
3. 서버와 로컬 시드 도구를 동시에 실행하지 않고, 하나의 프로세스/인스턴스만 사용.
   Gist PATCH와 현재 락은 분산 락이 아니므로 배포 겹침 중 소비자 호출도 중지해야 함.
4. 저장된 쿨다운 및 현재 제한 상황을 검토한 뒤 필요한 경우에만 로컬 로그인 1회.
   `last_error`가 사라진 것만으로 제한 해제를 판단하지 않음.
5. 읽기 전용 Garmin 조회 1회, 재시작 후 동일 `last_login_at`, 저장된 갱신 토큰 확인.
6. 무료 사용시간 확인 후 모니터 활성화, 30분 이상 실행 이력과 응답시간 확인.

**현재 Claude 예약 작업의 기존 깨우기 안내는 삭제하면 안 됩니다.**
다만 기존 서버의 시작이 인증을 유발할 수 있으므로 현재 429 사고 중에
깨우기 작업을 반복해서 시험하지 마세요. 운영 검증 후에도 간헐적인 재시작을
고려한 제한된 연결 재시도는 필요하며, 무료 환경에서 무중단을 보장하지 않습니다.

`/health`의 전체 응답 예시는 [README](../README.md#health)에 있습니다.
이는 성공 상태의 **예시**이며 실제 운영 응답이 아닙니다.
현재 고정 라이브러리는 OAuth1 만료일을 제공하지 않으므로 해당 필드는 `null`입니다.
운영 전제와 공식 출처는 [OPERATIONS.md](OPERATIONS.md)를 참조하세요.
